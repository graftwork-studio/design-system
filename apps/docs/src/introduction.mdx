# Graftwork design system

Components and tokens for Graftwork apps. Every component here is built on shadcn/ui with React Aria, and styled only with our semantic tokens.

## Using it in an app

```css
/* app/globals.css */
@import "tailwindcss";
@import "@graftwork/ui/styles.css";
@source "../node_modules/@graftwork/ui/dist";
```

```tsx
import { Button } from "@graftwork/ui";

<Button variant="primary" size="md">Save changes</Button>;
```

Apps never run `shadcn add`. If you need something that isn't here, add it to `@graftwork/ui`.

## Tokens in Tailwind

Only semantic tokens are available. Tailwind's default palette has been removed, so classes like `bg-blue-500` don't exist.

| What | Classes |
| --- | --- |
| Text | `text-text-default`, `text-text-secondary`, `text-text-link`, `text-text-error` … |
| Surfaces | `bg-surface-default`, `bg-surface-raised`, `bg-surface-subtle`, `bg-surface-overlay` |
| Scrim | `bg-overlay-scrim/60`, behind modal dialogs and sheets |
| Borders | `border-border-default`, `border-border-input` |
| Radius | `rounded-sm` (6px), `rounded-md` (8px), `rounded-lg` (10px), `rounded-xl` (14px), `rounded-full` |
| Type | `text-body` (14px: body text and the default for controls), `text-xs` … `text-4xl`, `leading-body`, `font-sans`. Text fields are 16px below 768px so iPhone Safari doesn't zoom in on them. |
| Spacing | Tailwind's numeric scale (`p-4` = 1rem), driven by the `space.2xs` token |
| Targets | `min-h-target-min` (24px), `hit-area` |
| Focus | `focus-ring`, `focus-ring-within`, and `focus-ring-drawn` for a part that shows its parent's focus |

## Accessibility built in

- Text is at least 4.5:1 against its background in every theme (WCAG AA), checked when tokens build.
- Every pointer target has a hit area of at least 24 × 24px (WCAG 2.5.8 AA). Component sizes follow shadcn/ui (aria-nova).
- Focus rings are 2px with a 2px offset, on `:focus-visible`, at least 3:1 against every surface.
- Light, dark and high-contrast themes follow the operating system, and the theme toggle overrides them.
- Under reduced motion, only opacity fades remain.
- Charts have a written summary and a table view, and never rely on colour alone.

## Component showcase

`ComponentShowcase` renders a working example of every component. Example pages use it, so new components appear on them with each package update:

```tsx
import { ComponentShowcase } from "@graftwork/ui/showcase";

<ComponentShowcase exclude={["ThemeToggle"]} />;
```

Use `exclude` for anything the page already shows. See it under **Showcase → All components**.

Where Figma and code differ:

- **Labels:** `label` on Checkbox, Radio and Switch is `children` in code. On Toggle, Badge, Kbd, Label and Tooltip, `children` is the text.
- **Layers, not props:** `DialogTitle`, `SheetTitle`, `PopoverTitle`, `TabPanel` and similar are the matching code components. Accordion's `title` and `content` are AccordionTrigger and AccordionContent. Collapsible's `trigger` and `content` are CollapsibleTrigger and CollapsibleContent.
- **Slots:** Figma can't take a component as a property. `startAddon`, `endAddon`, `action`, `icon` and `showShortcut` show or hide a slot, and `startAddonText` and `endAddonText` hold its text. In code, pass the content itself (`shortcut`, `startAddon`, `action`). AppShell's `showSidebarEnd` is its `sidebarEnd` slot, AppShellHeader's `showActions` is its `actions` slot (edit its breadcrumb's text directly), and AuthLayout's `showBrand`, `showFooter` and `showAside` are `brand`, `footer` and `aside`. AppShell's `variant` and `state` are set on the Sidebar you pass in.
- **Avatar:** `initials` come from `name` in code. Add a photo in Figma as an image fill; in code it's `src`.
- **Breadcrumb:** `isCurrent` means the item has no `href` in code.
- **Toast:** pass `title`, `description` and `variant` to `toast()`, with one `<Toaster />` in the app.
- **Code only:** Slider's two-thumb range and Tooltip's `placement`.
- **Set in code:** ToggleGroup's vertical `orientation` and `selectionMode`, Sidebar's `collapsible` behaviour (Figma shows `state`: expanded, collapsed) and CommandDialog, which is Command inside a modal.
- **Figma helpers:** SidebarMenuButton, CommandItem, QuestionnaireChoice, TraceLine, TraceCollapsible, CalendarDay and CodeBlockLine are their own Figma components so rows can be reused.
- **Figma states:** DatePicker and DateRangePicker use `state`: default, open, invalid, disabled. Command uses `state`, Questionnaire uses `hasError`, and ContextMenu uses `isOpen`. In code these come from props, validation and user interaction.
- **Example content:** `show…` properties hide a part of the design; in code, leave that part out. ButtonGroup's `style` picks an example layout, and text such as `item1`, `sender`, `time` and `value` is the content you pass in code.
- **Newest components:** Figma's Direction is `DirectionProvider` in code. Carousel's `position`, InputOTP's `state` and `isOpen` on HoverCard, Menubar and NavigationMenu show states that come from interaction in code. Set `href`, `placement`, `maxLength`, `errorMessage`, `defaultSize`, `minSize`, `locale` and CarouselItem's `aria-label` in code.
- **Code only:** DataTable's filtering, sorting and paging, and CodeBlock's syntax highlighting, wrapping and `startLine`.
